## The way I build

I’m interested in the moment an idea becomes something tangible: a tool with a clear purpose, an interface that feels considered, or a system whose behavior is easier to understand.

I don’t work in just one lane. My repositories explore a few connected themes:

<table>
  <tr>
    <td width="33%" valign="top">
      <p><strong><sub>01 / INTELLIGENCE</sub></strong></p>
      <h3>Make software more helpful.</h3>
      <p>Assistants, voice-driven interaction, contextual tools, and workflows that bring multiple capabilities into one place.</p>
    </td>
    <td width="33%" valign="top">
      <p><strong><sub>02 / CRAFT</sub></strong></p>
      <h3>Make tools feel coherent.</h3>
      <p>Desktop experiences, terminal utilities, automation, and the small implementation choices that make software easier to use.</p>
    </td>
    <td width="33%" valign="top">
      <p><strong><sub>03 / SYSTEMS</sub></strong></p>
      <h3>Understand what sits underneath.</h3>
      <p>Security research, distributed environments, and tooling that helps investigate how systems behave.</p>
    </td>
  </tr>
</table>
